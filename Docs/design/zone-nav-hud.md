# Zone navigation HUD (`/gvk`)

- **Drawn with the game's screen API** (SE 1.211: `MyScreenSpaceSprite`, `MyScreenSpaceText`, `MyModScreen`): the compass, zone bar, corner tactical radar, the satellite map, the settings screen and the [KOTH](koth-client.md) capture panel. The mod needs no other mod for its HUD. It used Text HUD API (Workshop 758597413) until 2026-11; that dependency, its F2 menu, the `/gvk ss` renderer switch and the billboard map are gone (merged into main and published 2026-11-23). A saved `UseScreenApi` in an old `GVK_ZoneNavConfig.xml` is skipped on load.
  - Layout is in HUD units (-1..1, Y up, 2 = the whole window), the units the HUD had under Text HUD API. `GvkScreenLayer` converts them to the screen API's space (which covers a centred 4:3 box, not the window) through window pixels. The layout code fills a draw list at the HUD refresh rate; `Draw()` replays it every frame (compass, radar, zone bar).
  - The screen API has no colour tags, so each coloured stretch of text is its own run placed after the last (`BeginRuns`, `AddRun`, `NewLine`).
  - Text size: Text HUD API sized text by the window height alone (its `FontTexture.cs` and `ModHUDMessage.GetLength`), while the screen API's font follows the player's UI scale. `GvkScreenLayer.MeasureTextScale` keeps the old size: scale = 0.13854 × window height ÷ the screen API width of `0123456789NESW` at scale 1, re-measured when the window or UI scale changes (logged as `Screen API text scale`). At 2560×1440 and the owner's UI scale that is 0.689, the value measured in game against Text HUD API on 2026-11-22.
  - The first tick with a player lays out the radar for the window (the zone bar's Radar Dock reads it even with the radar off) and names the map key loaded from the config.
  - Screen API drawing doesn't hide with the HUD on its own, so `Draw()` skips while `Session.Config.MinimalHud` is set. A draw error logs and turns that layer (HUD, map screen or KOTH panel) off for the session; the game keeps running.
  - **Satellite map as a game screen** (`GvkMapScreen`, a `MyModScreen`): while it is open it takes the mouse and keyboard, so the vehicle coasts, and it closes on Esc or the map key (the key that opened it must be let go first). If the game refuses the screen (four mod screens open), the player gets a notification. An error in the map's draw, input or build closes it at once (`CloseNow`, since a fading close of a screen opened that frame is lost) and keeps it off for the session (`FailMapScreen`); the settings screen does the same (`FailSettingsScreen`), and a refused settings screen also notifies. Each opening screen builds inside its own try, so an error is blamed on the screen it came from. Every open makes a new `GvkMapScreen` or `GvkSettingsScreen`: the game removes a closed screen a frame after `OnClosed`, and that removal would close a reopen on the same `MyModScreen` (its `DeliverClosed` doesn't check the host). The KOTH capture panel hides while the map is up, like the rest of the HUD (`KothClientData.MapOpen`). It draws the map through a view: mouse wheel zooms about the cursor from the whole map (1×) to 3×, the picture's limit, and a left-button drag pans; it reopens centred on the player at the last zoom. The map picture and KOTH rings are clipped to the frame (`BeginClip`), and markers outside the frame are left out so labels near an edge stay whole. Pointing at a marker or label shows its full name, what it is (GPS point; your, faction, hostile, NPC or neutral signal; KOTH open now or opens next; Alliance base site, trade station, scrap refinery, Alliance supply depot or Alliance carrier) and its distance. Right-click opens a small menu rather than acting at once, since stray clicks made piles of GPS points (owner, 2026-11-22): on empty map it marks the spot and asks "Add a GPS here?", on a GPS marker or label it names the GPS and offers **Hide**, **Delete** and **Cancel** (owner, 2026-11-24: "add the option to hide a GPS when you right click on it, so you can hide/delete/cancel"; signals, KOTH and known-site markers aren't GPS points). Hide turns the GPS's Show on HUD off (`SetShowOnHud`), so it leaves the map, compass and radar but stays in the GPS list; Delete removes it. Enter or the first button (Add GPS, or Hide) confirms; Cancel, a click elsewhere, the wheel or Esc closes the menu (Esc closes the menu before the map, through `OnCancelling`). An added GPS goes on the ground there as `Map Point N` (the next free N): the map projection run backwards gives the direction from the planet centre, then `MyPlanet.GetClosestSurfacePointGlobal` the ground. Hiding and deleting find the GPS again by name and position. The controls line sits on its own card under the frame, at text scale 0.62 (0.46 was too small to read).
    - **Filter buttons** (owner, 2026-11-24: "can we put the satellite map filter options also on the satellite map view? I'd like them as little buttons or icons on the side"): a column of icon buttons on its own card docked to the right of the frame, one per Satellite Map setting except the map key: KOTH, Own & Faction Signals, Bases & Stations, Alliance Territory, Safety Zones, GPS Labels, Signal Labels, Stack Icons (`MAP_FILTER_IDS`). A click runs the same `DoSetting` as the settings row, so it saves and notifies, and the map redraws at once. On shows the icon white with a light bar on the left, off dims it; pointing at one shows "Setting: On/Off" to its left. The icons are white with a baked black outline like the site icons (`MapBtn_Signals`, `MapBtn_GpsLabels`, `MapBtn_SignalLabels`, `MapBtn_Stack`; KOTH reuses `POI_KOTH`, the crown, given the outline too (owner, 2026-11-24: "the crown icon needs the black outline"), and Bases & Stations `POI_SiteBase`). Alliance Territory and Safety Zones each have four states and an icon per state (below). They are drawn on the button layer, rebuilt every input frame with the Settings button, and once more without hover when the map closes, since its fade gets no input frames. Map labels that would run past the frame's right edge, under the buttons, go on the marker's left instead.
  - **Settings screen** (`GvkSettingsScreen`, `/gvk settings` or the **Settings** button at the right end of the map header): every navigation setting, in tabs (General, Radar, Compass, Satellite Map, Performance). Click a row to toggle or cycle it through the same methods the chat commands use, so each change saves and notifies. Position rows are sliders: press on the track and drag; the radar or compass moves live and saves once on release. Map Key: click, then press the new key (with any Shift, Ctrl or Alt); Esc or a click cancels, and mouse buttons and modifiers alone are ignored. Snap Position reads Custom when the element is not at a preset. Factory Reset needs a second click. Esc or Close shuts it. Opened from the map (its button, or `/gvk settings` while the map is up), it closes the map and reopens it with the same view on close: a new game screen hides the one under it, and the HUD isn't drawn while the map is up, so the sliders' live move would be out of sight. It replaced the Text HUD API F2 menu (owner, 2026-11-22: "yes settings screen, I'd like a button in the = satellite map to get to the settings too").

- **Unified Top-Right Tactical Radar & Zone HUD**:
  - **Live Corner Radar (Top-Right)**: until 2026-11-25 the corner minimap could also show the whole map (Strategic Map, "SECTOR MAP"); the owner dropped it ("I kinda want to disable the minimap feature and just leave it as the radar on the player hud"), with its Mode, Alliance Territory and Safety Zones rows and its own `/gvk radar` (Tactical/Strategic).     - **Tactical Vector Radar**: Player-centered combat vector radar with:
      - **Camera-Facing Orientation & High-Visibility Player Reticle**: The radar aligns directly to your live camera view / line-of-sight in real time. Your rover/character forward heading is designated by an enlarged, high-visibility **Electric Gold / Amber pulsing chevron** layered over a **deep black contrast backing**, ensuring instantaneous visual distinction against all terrains and signals. Own-grid cockpit and antenna waypoints (< 30m) are automatically suppressed to keep the center reticle 100% clutter-free.
      - **Dynamic FOV View Cone ("V" Indicator)**: Two razor-thin tactical cyan HUD rays (`0.0008f`) radiate upward from the center crosshair out to the radar perimeter, forming an authentic avionics "V" frustum that precisely tracks your camera's active on-screen viewport. Dynamically widens and narrows in real time with your in-game Field of View and camera/sniper/turret zoom levels! Any contact inside the "V" is directly visible through your windshield/screen.
      - **Concentric Range Rings**: 1km, 2km, and 3km rings with cardinal crosshairs and heading indicator.
      - **Dual Scaling Modes (Linear vs Logarithmic)**:
        - **Linear Scale**: Selectable combat scanning ranges: 1.5 km, 3.0 km, and 5.0 km (`/gvk range` or the settings screen).
        - **Logarithmic Scale (0 - 30 km)**: Compresses the desert combat theater out to the planetary horizon using a 3-decade logarithmic scale: Inner ring $= 300\text{ m}$ (dogfight/CQB range), Middle ring $= 3.0\text{ km}$ (visual line-of-sight / standard engagement), Outer ring $= 30.0\text{ km}$ (planetary horizon / edge of planet curvature). Contacts beyond 30 km (up to 100 km) max out to the outer perimeter ring.
        - Broadcast radio contacts (beacons and antennas) dynamically update their tactical icons based on true spherical planetary elevation relative to your vehicle (comparing radial altitude from Pertam's core, preventing planetary curvature from incorrectly flagging distant airborne contacts as 'below'):
          - **Upward Arrow** (`signal_up`): Target is $> 200\text{ m}$ above you.
          - **Equal Icon** (`signal_level`): Target is within $\pm 200\text{ m}$ altitude of you.
          - **Downward Arrow** (`signal_down`): Target is $> 200\text{ m}$ below you.
        - Faction relation colors (Allied green, Enemy red, Neutral white, NPC gold, Self cyan) remain active to show alignment, while GPS waypoints continue using their distinct GPS marker dots.
        - **Subtle Drop Shadow & Contrast Halo**: Every HUD contact texture (`signal_up`, `signal_down`, `signal_level`, `nav_arrow`, and custom `marker_gps` dot) features an avionics-grade soft black drop shadow halo. This guarantees instant, crystal-clear readability against blinding desert sands, harsh sunlight, terrain clutter, and night skies alike.
      - **Local Tangent Projection**: Projects true relative distances along Pertam's local horizon plane.
      - **Perimeter Zone Direction Vectors**: Tactical vector rays spin around the outer 1/3rd perimeter ring of the radar (leaving the center 2/3rds completely unobscured for CQB contacts and reticles) in the accent color of the nearest lower zone (Lime Green / Yellow) and higher zone (Orange / Red), dynamically rotating with your live camera view and vehicle heading.
    - **Zone Status Panel**: Shows your zone from the MES zone spheres (`ClassifyZone`). Zone 0 wins where it overlaps Zone 1; otherwise the highest sphere you are inside wins. Outside every sphere (the sky just past the Zone 0 edge) counts as Zone 1, as in `GVK_NoPVPZone.cs` and the production limits.
    - **Integrated Tactical Header Box**: The mode and range telemetry (`TACTICAL RADAR (LOG: 30 KM)`) is cleanly framed in crisp white text inside a docked header card directly above the radar, matching the exact width of the radar card with a tactical grey accent strip on the left edge.
    - **Dynamic HUD Background Transparency & Palette**: All HUD element background cards (compass ribbon, zone status panel, tactical radar box, full satellite map frame, and map header) are rendered in Keen's signature HUD slate blue (`#29363E` / `RGB 41, 54, 62`) and automatically match the player's native Space Engineers **HUD Background Opacity** game setting in real time.
    - **Settings screen**: `/gvk settings` (see above), with each value shown in colour on its row.

  - **Known sites** (bases and stations without a GPS point; owner, 2026-11-24: "can we integrate it with the MES base site encounters to see where they are on the map without players needing to save GPS signals?", "same for trade stations?"): the 22 Base Sites, the trade stations (Sevastopol, Skyport, Mastodon, Rusty's, Coalition Base, both Vehicle Stores, the four KOTH Camps), the Scrap Refinery, the four Supply Depots and the two Carriers. Positions come from each MES spawn group's `[StaticEncounterCoords:]`, read once from the spawn group definitions every client loads with GVK_Derelicts (`GvkKnownSites` in `GVK_SiteStatus.cs`). Groups are picked by SubtypeId (the table in `GvkKnownSites`, plus the `GVK-Alliance-PresetBases-Site-SpawnGroup-` prefix named by each prefab's beacon text), since the static files also hold signposts, bridges and chunks; a table entry that matches no usable group is logged once. The parse follows MES: the `[Modular Encounters SpawnGroup]` header, `[StaticEncounter:true]`, the last coords tag, and no `[StaticEncounterUsePlanetDirectionAndAltitude:true]`.
  - **Site status** (owner, 2026-11-24: "show the status like if there is a base spawned there and which alliance faction it is with either green/white/red depending on relation"): the server (`GVK_SiteStatus` session component) checks every site 10 s after load and then once a minute, and sends the list on channel 47411 (the KOTH plugin uses 47410) to every client when it changes; a client asks for it 5 s after joining. A Base Site is held when a static grid of an NPC faction other than UNKN stands within 600 m (a claimed Base spawns 200-500 m off its site; the nearest Base Site takes it), unclaimed when only its UNKN placeholder stands at the coords, and not spawned otherwise. Any other site is up when an NPC-owned grid's origin is within 25 m of its coords, owned by that grid's faction; a player's grid parked there never counts. MES spawns statics only when a player comes near, so a far site reads not spawned until someone has been there. One line per site, `SubtypeId`, state, faction id, tag, tab-separated, a few kB at most; a host or single player reads the scan directly.

Trade stations and the refinery stay white. A Base Site with no alliance Base, and any site the server reports not spawned, is dimmed grey. The colour is re-read every scan, so a standing change shows within a refresh.
  - **Alliance territory** (owner, 2026-11-24: "can we also show a ring to show the radius of the alliance influence?", "is it possible to have it contour to the way that Mercator maps stretch at the top and bottom?"): the satellite map draws each alliance's territory, the MES zone `SOBAN_Zone` or `KHAANEPH_Zone` (a sphere around its carrier), as a dashed ring with an edge band inside it, in the player's standing colour with that alliance. Centres and starting radii come from the zone profiles (`GVK-Alliance-Zone-<tag>`, `[Coordinates:]`, `[Radius:]`) every machine loads with GVK_Derelicts; the size comes from the server, which reads the `<tag>_Tier` sandbox counter (km) that the Influence ladder (`GVK-Alliance-Events-ZoneSize.sbc`) writes as it resizes the zone, and sends it with the site status (`@T` lines; 0 = the profile's radius). A ring shows only once the server has sent its size.
    - The map picture (`KharakMercator.dds`) is not Mercator: `WorldToMapUV` is equirectangular, so north-south is true everywhere and east-west stretches by 1 / cos(latitude). The ring follows it by construction: the sphere meets the ground (sea level, 30 km) in a circle of angular radius A, cos A = (R² + d² - r²) / 2Rd; points 100 m apart round that circle on the globe go through `WorldToMapUV`. The ring is drawn exactly like the safety zone lines (below), in even dashes 0.010 HUD units long with 0.006 gaps, about 10 and 6 px at 1080p (owner, 2026-11-25: "I said I wanted them consistent other than they are dotted", "do the alliance zones the same way just with some equal spacing between segments").
